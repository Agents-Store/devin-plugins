# Upstream behaviour worth recognising

Known defects and documented-but-surprising behaviour of the runtime itself, written to be recognised
**by symptom**. There are no issue numbers here on purpose: they go stale, they get renumbered, and a
number invites citing a tracker instead of looking at the box.

Two rules for using this page:

- **Status is a hint with a shelf life.** `open`, `fixed` and `by design` describe the last review, not
  today. Before recommending anything on the strength of a row here, confirm the current position with
  the `docs-research` skill and with the runtime's own documentation on the instance in front of you.
- **Never fix by analogy.** A matching symptom is a hypothesis. Confirm it with the check in
  `findings-catalog.md` before acting; several rows below produce the same visible symptom.

## Defects

| Symptom | Cause | Status | What it means here |
|---|---|---|---|
| Several instances get logged out from one provider in waves; unauthorized errors arrive in bursts with a reused-refresh-token reason, and each failure cascades into the fallback chain | Several consumers share one OAuth account through **separate copies** of its credentials. Refresh tokens are single-use and rotate on every refresh, and the provider invalidates the previous one, so the last refresher wins and the rest are logged out. The runtime's serialisation lock is a **file lock inside one state directory** and cannot serialise across copies. Not provider-specific: any OAuth provider doing refresh rotation with reuse detection behaves this way | open | The architectural fix is one owner per refresh chain: one credential directory mounted into every container, everyone else re-reads. Sidecar prefresh loops are a mitigation for a single owner, not a substitute for one. Catalog: `fleet.auth.token-sink` |
| A CLI backend reports "not logged in" although credentials are mounted and readable | The environment variable that selects the CLI's credential directory is not inherited by the subprocess; the CLI goes to the home directory instead | open | Pass the directory explicitly when invoking the CLI inside the container, and make the mounted location match what it will actually read. Catalog: `fleet.auth.orphan-runtime`, `fleet.auth.emptied` |
| Sessions start failing with an expired-session error some time **after** an otherwise successful upgrade | Config migration silently rewrote the primary from the CLI-backed reference to a provider reference and dropped the runtime override | open | Always snapshot before upgrading, and check the runtime override right after. The failure arrives late, so an upgrade that "looked fine" is not evidence. Catalog: `fleet.model.primary-overwritten` |
| A skill was installed globally, the files are on disk, and nothing loads it | The global install copies files without registering them | open | Never manage shared assets through the global install path. File layout plus config registration only. Catalog: `fleet.shared.install-global-invisible` |
| Installing one skill removes the others | A corrupted install lock file; the next install rewrites the set from a broken lock | open | Back up and read the lock before any install. One failure means stop, not retry. Catalog: `fleet.shared.lock-corrupt` |
| The state database keeps growing; memory tables dominate it | Chunk and embedding-cache tables have neither retention nor an eviction policy, and embeddings are stored as text | open | Retention is an operator procedure with no upstream support: back up, stop, delete old **cache** rows only, compact, restart, smoke test. Never touch the index itself. Catalog: `fleet.memory.db-growth` |
| Memory search stays poor after the embedding provider was fixed | Search stuck on the fallback model after the provider outage | open | Only a full gateway restart clears it — a reload does not. Any instance that sat in a provider outage for a long time is a candidate. Catalog: `fleet.memory.search-stuck-fallback` |
| After an upgrade, scheduled jobs fire two or three times per tick and some lose their agent binding | The upgrade duplicated schedule entries; the copies stay enabled | open | Deduplicate as part of every upgrade, keeping the entry that still has a binding. Check it first wherever a schedule moves money. Catalog: `fleet.cron.duplicates-after-upgrade` |
| A timer stops firing permanently while everything else keeps working | A run of timeouts kills the timer for good | open | Recreate the entry. Only fire-time history reveals it; a status read shows nothing wrong. Catalog: `fleet.cron.timer-dead-after-timeouts` |
| Timers stall for hours on a nightly cadence and then catch up in a burst; the process stays active and the status stays green throughout | Not diagnosed upstream | open | Only an outside observer with history detects this. Keep expected-versus-actual fire times per job and alert on drift; do not go looking for it in a status output. Catalog: `fleet.cron.night-stall` |
| A container is reported unhealthy indefinitely while its health endpoint answers correctly | Healthcheck definition, not the application | fixed | On an old instance, prefer the endpoint over the container's health flag; after upgrading, expect the flag to become meaningful again. Catalog: `fleet.liveness.health-vs-ready` |
| The config you edit has no effect, and the instance behaves as if it were reading something else | When the configured state directory is absent, the resolver falls back to a legacy directory instead of failing | open | Confirm the state directory from the mount table **and** from the running process before editing anything. Catalog: `fleet.inventory.state-dir-fallback` |
| A version line you were waiting for never ships | Release lines can die in pre-release without ever being promoted | open | Never plan around "we will upgrade when version X arrives". Plan around the channel plus a soak window. Catalog: `fleet.version.soak-not-met` |

## Documented behaviour that reads like a defect

| What you see | Why | Operational consequence |
|---|---|---|
| The gateway is stopped after an upgrade instead of running degraded | By design: if startup repairs cannot complete safely, the gateway exits rather than reporting healthy | Treat it as a failed upgrade and restore. Restarting in a loop is the wrong reflex — zero retries. Catalog: `fleet.upgrade.gateway-stopped` |
| An upgrade cannot be rolled back | State-schema migration runs in place with no pre-migration backup; a restore path exists only in pre-release and only into a clean target | The tar of a **stopped** state directory is the only real rollback. Stop first, then archive: stopping is what makes the copy consistent. Catalog: `fleet.upgrade.no-verified-backup` |
| The readiness endpoint returns a bare negative with no reasons | Readiness detail depends on authentication | Query it with the bearer or you are diagnosing blind. Catalog: `fleet.liveness.health-vs-ready` |
| The health rollup says everything is fine while messages are not being delivered | The top-level flag does not include delivery-queue depth | Check queues explicitly; never treat the rollup as a completeness statement. Catalog: `fleet.liveness.queue-backlog` |
| Bulk-approval flags refuse to approve new capabilities | Deliberate: non-interactive and silent setup cannot grant capability consent, and neither can the automatic repair flag | The plugin prints the consent line for a human. Automating it removes the mechanism, so it is a hard ban. Catalog: `fleet.security.capability-consent-pending` |
| Vector search is paused with an index-identity warning after a key change | Index identity is derived from the provider configuration, including the key | Changing an embedding key forces a full reindex on **every** instance where it changed, including ones where the key was "just replaced". Catalog: `fleet.memory.index-identity-changed` |
| Embedding calls fail even though the chat path works on the same account | A subscription OAuth session covers chat completions and does not satisfy embedding requests | Embeddings need a real API key. This is the usual cause of a fleet-wide dead index that looks like an expiry problem. Catalog: `fleet.memory.embeddings-unauthorized` |
| A shared skill directory is mounted, populated, and nothing loads from it | Extra skill directories are the **lowest** load priority, and a leftover local copy shadows the shared one; separately, a bind mount whose ownership the runtime distrusts is refused as a candidate | Sharing is not done until you have proved which path a loaded asset came from. Catalog: `fleet.shared.local-shadow`, `fleet.shared.ownership-blocked` |
| A model or provider goes quiet for a long stretch after payment problems | Billing failures produce a long backoff rather than an immediate error | Look for the disabled-until marker after any billing incident; it outlives the incident. Catalog: `fleet.model.disabled-until` |
| Requests are slower than they should be even when they succeed | Auth-profile rotation runs through every profile of a provider **before** moving to the next model in the chain, and each dead profile costs a retry plus a cooldown | Delete dead profiles instead of leaving them "in case". Catalog: `fleet.auth.dead-profile` |
| One CLI provider's consumer OAuth login can no longer be set up | The provider withdrew that route; the runtime no longer offers new logins for it | Existing profiles of that kind are legacy. New setups use an API key or the provider's cloud platform path — confirm the current form with `docs-research` before writing it into a config |
| A profile copied from another instance authenticates for a while and then fails oddly | API-key and static-token entries are portable; OAuth entries are not | Never copy an OAuth profile. Share by mounting one owner directory, or log in per instance. Catalog: `fleet.auth.oauth-copied` |
| A moving image tag "did not change" and then behaves differently | Moving tags are rebuilt on their own schedule; only plain version tags and dated tags are immutable | Pin a digest or a plain version for anything you intend to reason about later. Catalog: `fleet.version.moving-tag-pin` |
| A version chosen as "the newest stable" turns out to be older than what the channel actually offers, or misses a correction release | Version ordering treats correction suffixes as pre-release, and release listings sorted by date surface the trailing channel; promotions can also happen without a version bump | Resolve the target from registry dist-tags only. Catalog: `fleet.version.channel-misread` |
